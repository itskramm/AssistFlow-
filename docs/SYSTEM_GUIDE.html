01 System Overview

What SmartOpsSupportHub is, what problem it solves, and who it is for.

SmartOpsSupportHub is an AI-powered workplace support system built specifically for call center agents. It gives agents instant, step-by-step guidance on company procedures, system errors, and troubleshooting workflows — without requiring them to leave their main workspace or search through folders of documents.

The system uses Retrieval-Augmented Generation (RAG) — a technique that combines a searchable knowledge base with a large language model — so every answer is grounded in real company SOPs rather than the model's general training data.

🎯

The Problem

Call center agents waste time searching PDF folders and document portals for the right procedure while a customer is waiting on the line.

💡

The Solution

A conversational AI assistant that retrieves the right SOP instantly and presents it as numbered action steps in a familiar chat interface.

🔒

Key Guarantee

Answers are always grounded in internal documents. The system clearly labels when it falls back to general knowledge and never invents company policy.

📡

Always Available

39 offline protocols are cached in a local SQLite database. The assistant continues working during full internet or backend outages.

Thesis context: This system was developed as a thesis project titled "Design and Development of an AI-Assisted Workplace Support System for Improving Workflow Efficiency and System Usability."

Data flow for a typical request

1

Agent types a question

The web app or extension sends a POST request to /api/chat with the message, recent conversation history, and optional CRM page context.

2

Connectivity check

The backend probes generativelanguage.googleapis.com:443. If unreachable, it goes directly to the SQLite offline cache — skipping Gemini entirely.

3

Query embedding and retrieval

The query is embedded using gemini-embedding-001 and compared against all stored SOP chunks in ChromaDB. The top-4 closest chunks (distance ≤ 0.4) are returned.

4

Response mode selection

The system checks whether the retrieved chunks actually support the query. If yes → GROUNDED mode (uses SOP chunks). If no → GENERAL mode (uses Gemini's broad knowledge, clearly labelled).

5

Gemini generation

The retrieved chunks, conversation history, and CRM context are injected into the system prompt. Gemini generates a numbered step-by-step response.

6

Response returned

The API returns reply, source (rag / general / offline-cache / fallback), latency_ms, and retrieved_sources.

05 RAG Pipeline — How Retrieval Works

The step-by-step process from question to retrieved context.

What is RAG?

Retrieval-Augmented Generation (RAG) separates knowledge from the language model. Instead of relying on what Gemini memorised during training, the system first retrieves the most relevant passages from your specific documents, then asks Gemini to answer using only those passages — ensuring every answer is traceable to a real source document.

Ingestion (one-time setup)

1

Read documents

The ingest script reads all .md files from backend/data/knowledge/.

2

Chunk

Each document is split into overlapping text chunks so individual procedures can be retrieved without loading the full document.

3

Embed

Each chunk is converted to a vector using gemini-embedding-001. Semantically similar text produces similar vectors.

4

Store

Vectors are stored in ChromaDB at data/chroma/ with the source filename as metadata.

Query-time retrieval parameters

ParameterValueWhat it means
Embedding modelgemini-embedding-001Converts the agent's question into a vector
Top-K4Returns the 4 closest document chunks
Distance threshold0.4Chunks further than 0.4 are discarded as irrelevant
Context windowLast 8 turnsPrevious conversation is included in the retrieval query
CRM contextOptionalTicket subject/description from the page is added to the query

Response mode logic

  • GROUNDED — retrieved chunks match the query → Gemini answers using SOP text → badge: AI · SOP
  • GENERAL — no relevant chunks → Gemini answers from general knowledge, clearly labelled → badge: General guidance
  • OFFLINE — no internet → SQLite keyword match → badge: Offline cache

06 Gemini API Integration

How Google Gemini is used for both embedding and generation.

🔢

Embedding Model

gemini-embedding-001 — converts text into numerical vectors for semantic search.

💬

Generation Model

gemini-3.1-flash-lite — generates the final answer. Temperature 0.2 keeps responses factual and consistent.

System prompt behaviour

  • Format responses as numbered step-by-step instructions
  • Ask exactly ONE clarifying question if the query is too vague — never multiple questions
  • Never invent company policies or internal contacts not in the retrieved context
  • Use existing conversation turns as context — don't ask for information already provided
  • Clearly label answers as "General guidance" when not backed by a company SOP

Retry logic

Attempt 1: immediate
Attempt 2: 1.5s delay
Attempt 3: 3.0s delay
Network error: skip all retries → SQLite fallback

Health polling

When offline is detected, the frontend probes GET /api/health every 30 seconds and transparently returns to online mode when the backend responds — no user action required.

10 Performance Evaluation

How the system's performance is formally measured.

🎯

Retrieval Precision

Precision@K — did the expected source appear in top-K results? Also reports MRR and per-category breakdown.

✅

Generation Accuracy

Phrase coverage — what % of reference key phrases appear in the answer? Reports full match rate and average coverage.

⚡

Latency

p50 / p95 / p99 response times for online (full RAG) and simulated downtime (SQLite only) modes.

Simulated downtime

The downtime evaluation patches _check_internet() to always return False, forcing every request through the SQLite offline cache without a real network outage.

# Full evaluation suite
python scripts/evaluate_rag.py --mode all --output results.json

# Individual modes
python scripts/evaluate_rag.py --mode retrieval   # Precision@K + MRR
python scripts/evaluate_rag.py --mode generation  # Phrase coverage
python scripts/evaluate_rag.py --mode latency     # Online p50/p95/p99
python scripts/evaluate_rag.py --mode downtime    # Offline latency simulation

11 Setup & Deployment

How to run the system locally and in production.

Prerequisites

  • Python 3.11 or newer
  • Node.js 18 or newer
  • Google Gemini API key
  • Google Chrome 114+ (for extension)

Local setup

# 1. Clone
git clone https://github.com/itskramm/AssistFlow-.git
cd AssistFlow-

# 2. Backend
cd backend
cp .env.example .env        # add your GEMINI_API_KEY
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd ..

# 3. Build knowledge index (once)
python scripts/ingest_knowledge.py

# 4. Start backend
cd backend && python run.py

# 5. Start web app (new terminal)
cd webapp && npm install && npm run dev
